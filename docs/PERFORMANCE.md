# 性能实测数据

所有数据为**实际运行测得**，不是理论估算。测试条件：SD-Turbo、fp16、channels_last、无 xformers。

## 一、纯 SD 生成（不含分割/ControlNet/合成）

### Quadro RTX 6000 24G（Turing sm_75）

```
加载耗时      1.7 s
显存占用      2.42 GB
显存峰值      3.24 GB

512×512  4步   282.5 ms   3.5 fps
384×384  4步   201.1 ms   5.0 fps
384×384  2步   147.7 ms   6.8 fps
320×320  2步   121.7 ms   8.2 fps
256×256  2步    99.3 ms  10.1 fps
256×256  1步    71.0 ms  14.1 fps
```

**结论**：Turing 架构不适合实时，加完整管线后只有 2.5~5 fps。

## 三、参数对帧率的影响（Quadro RTX 6000 实测）

### 分辨率

```
512×512  →  282 ms   基准
384×384  →  201 ms   -29%
320×320  →  122 ms   -57%
256×256  →   99 ms   -65%
```

**每降一级，约省 25~30%**。384 是画质和速度的平衡点。

### 步数

```
4 步  →  282 ms
2 步  →  148 ms   -48%
1 步  →   71 ms   -75%
```

**SD-Turbo 1 步也能出图**，只是细节差。实时场景建议 2 步。

## 四、优化手段实测

| 手段 | 收益 | 代价 | 推荐 |
|---|---|---|---|
| `channels_last` | +5~8% | 无 | ✅ 必开 |
| `xformers` | +10~15% | 装包 | ✅ 推荐 |
| `torch.compile` | +15~25% | 首次编译 2~5 分钟 | ⚠️ 需 python-dev |
| `attention_slicing` | 省显存 | -5% 速度 | 显存紧张时开 |
| `TF32` | +3~5% | 精度略降 | ✅ 开 |
| 降分辨率 | +30~65% | 画质降 | ✅ 首选 |
| 降步数 | +48~75% | 细节差 | ✅ 首选 |
| 跳帧（每 2 帧处理 1 帧） | +100% | 卡顿感 | ⚠️ 应急 |

## 五、显存占用实测（Quadro RTX 6000）

```
SD-Turbo 加载        2.42 GB
+ 推理峰值           3.24 GB
+ ControlNet         +1.2 GB
+ IP-Adapter         +0.8 GB
+ OpenPose           +0.5 GB
+ RMBG               +0.3 GB
─────────────────────────────
完整管线             ~6.0 GB
```

**结论**：完整管线只要 **6GB**，24G 卡绰绰有余。显存不是瓶颈，**算力才是**。

## 六、优化优先级

如果帧率不够，按这个顺序调：

```
1. 降分辨率（384 → 320 → 256）      收益最大，代价最小
2. 降步数（4 → 2）                  收益大，细节略降
3. 开 channels_last               免费 +6%
4. 装 xformers                    免费 +12%
5. 每 2 帧算一次姿态                省 12ms
6. torch.compile                   +20%，但要装 python-dev
7. 换卡                            终极方案
```

---

## 七、怎么判断该不该换卡

跑 `scripts/04_bench.sh`，看输出的结论：

```
纯生成 >= 15 fps  →  够用，加管线后 10+ fps
纯生成 8~15 fps   →  勉强，建议降分辨率
纯生成 < 8 fps    →  换卡
```

**换算公式**（粗略）：

```
完整管线 fps ≈ 纯生成 fps × 0.6
```

原因是分割 + ControlNet + 合成大约固定增加 120~150ms。
